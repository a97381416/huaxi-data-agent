# 文件问答功能迁移方案（M5，从 0 到 1 移植指南）

> 目标读者：要把本项目的"M5 文件问答"（上传解析 + RAG 检索 + 图片多模态识别）能力移植到**另一个 Agent 项目**的开发者。
> 参考实现：本项目 M5 里程碑，代码集中在 `dataagent/file/` 包 + `AnalyzeFileTool` + `SessionFilesPromptBuilder` + `DodoAgent` 接入点。
> 阅读前提：目标 Agent 是 Spring Boot 后端 + 浏览器前端，Agent 有"system prompt 拼装 + 工具注入 + 流式事件"三处可挂钩的扩展点。

---

## 1. 一分钟版：这个功能是什么，靠哪几个设计决策撑起来

**用户视角**：聊天框选文件上传（PDF/Word/Excel/图片/文本…），文件出现在消息气泡上；发送后 Agent 能回答关于文件的问题——小文件直接读全文，大文件按问题语义检索相关片段（RAG），图片自动"看图说话"，多轮追问、跨轮指代（"上一篇讲了什么"）都可用；历史会话回放时每轮消息还能看到当轮附件。

**实现视角**：上传链路（`/api/files/upload` → Tika 解析 → MinIO 落盘 → 大文件切分向量化）与问答链路（system prompt 文件清单段 → LLM 主动调 `analyzeFile` 工具取内容）两条线，靠一张 `agentx_file` 元数据表串起来。**文件内容不进上下文，靠工具按需加载**——这是和"把文件塞 prompt"路线的根本区别。

迁移时不许走样的六个核心设计决策：

| # | 决策 | 为什么 | 落点 |
| --- | --- | --- | --- |
| D1 | **类型路由**：文本类走 Tika 解析、图片只落存储不识别、其他仅存元数据 | 上传要快；图片识别烧钱，推迟到真正被问到 | `FileManageService.uploadFile` |
| D2 | **embed 标志**：全文 ≥ 阈值（默认 1 万字符）才切分向量化（embed=1），否则只存截断文本（embed=0） | 小文件 RAG 反而更慢更差；截断到 2 万字符直接塞得下 | `handleTextFile` |
| D3 | **analyzeFile 三路路由**：LLM 只拿 fileId + question，按 DB 的 fileType + embed 分发到 图片多模态 / RAG 检索 / 直接加载 | LLM 不需要知道文件类型，工具 schema 只有一个 | `AnalyzeFileTool` |
| D4 | **双阶段关联**：上传时不归属会话；stream 启动时 linkToConversation（本轮 prompt 立即可见），Complete/Paused 事件后 linkToSession 补写轮次（历史回放按轮取附件） | 上传和提问是两个独立请求；conversation 先行保证当轮可用，session 补写保证回放分组 | `FileManageService.linkToConversation/linkToSession` |
| D5 | **懒缓存**：图片首次被 analyzeFile 才调多模态识别，结果写回 extracted_text，下次直接命中 | 同一张图不重复烧多模态调用 | `AnalyzeFileTool.handleImage` |
| D6 | **全链路降级**：MinIO 宕机上传明确报错；pgvector/embedding 不可用则 embed=0 直接加载；多模态未配置给友好提示——**主问答流程永不因文件设施挂掉** | 文件问答是增强能力，不能拖死核心对话 | 各 Config 的 `@ConditionalOnProperty` + EmbeddingService 空安全 |

另有一个**条件注入**细节：会话里存在文件时才把 analyzeFile 注入工具列表（`DodoAgent.availableTools`），闲聊不浪费工具 schema 与 token。

## 2. 总体架构

### 2.1 上传链路（独立于对话请求）

```
前端 ChatView                FileController            FileManageService                外部设施
   │ POST /api/files/upload      │                          │
   │ ──────────────────────────► │ upload(file)             │
   │                             │ ────────────────────────►│ ① insert agentx_file(PROCESSING)
   │                             │                          │ ② MinIO putObject ─────────► MinIO
   │                             │                          │ ③ 类型路由：
   │                             │                          │    文本 → Tika 解析 ────────► (本地)
   │                             │                          │        全文≥1万 → 切分500/50
   │                             │                          │        → embedAndStore ────► PG pgvector
   │                             │                          │        + EmbeddingModel ───► DashScope
   │                             │                          │    图片 → 不识别（留 analyzeFile）
   │                             │                          │ ④ update status=SUCCESS, embed=0/1
   │ ◄── {fileId, embed, ...} ── │                          │
```

### 2.2 问答链路（文件进上下文的唯一入口是 analyzeFile 工具）

```
前端 send()                  AgentController / Agent 门面                    LLM
   │ POST /agent/stream          │
   │  {query, fileIds[]}         │
   │ ───────────────────────────►│ ① linkToConversation(fileIds, convId)  ← 阶段一关联
   │                             │ ② instructions += SessionFilesPromptBuilder
   │                             │    （本次新上传组 + 历史按轮 + 指代触发规则）
   │                             │ ③ 会话有文件 → 工具列表追加 analyzeFile   ← 条件注入
   │                             │ ④ ReAct 循环 ───────────────────────────► "总结这些文件"
   │                             │    ◄───────── tool_call analyzeFile ────── 逐个 fileId 调用
   │                             │    三路路由：图片→多模态 / embed=1→RAG / 其他→全文
   │ ◄── TEXT/TOOL_* 事件流 ─────│ ⑤ Complete/Paused 事件带 sessionId
   │                             │    → linkToSession(fileIds, sessionId)   ← 阶段二关联
```

### 2.3 迁移不变式（六条）

1. **文件内容不进 system prompt**：prompt 里只有文件清单（fileId/文件名/类型）和触发规则；内容一律由 LLM 调 analyzeFile 按需取。大文件全塞 prompt 是事故。
2. **fileId 是唯一钥匙**：对外只暴露 UUID fileId，objectName、DB 主键都不出边界。
3. **触发规则写进 prompt**（指代消解口径）："这个/这些/分析下" → 本次整组挨个加载；"上一篇/上一个" → 历史最新一轮；闲聊不调。没有这段话，LLM 要么不调工具要么只调第一个。
4. **阶段一关联必须发生在 ReAct 循环启动前**，否则本轮 prompt 反查不到刚上传的文件；阶段二挂流终态事件，失败仅 warn 不阻断。
5. **降级路径必须保通**：每条外部依赖（MinIO/PG/embedding/多模态）缺失或宕机都有明确行为，见 §12 降级契约表。
6. **系统表对 Agent 隐藏**：`agentx_file`、`vector_file_info` 等不得出现在 Agent 可见的 schema 里（本项目用 `mschema.exclude-tables: agentx_*`，向量表在独立 PG 库天然隔离）。

## 3. 第 0 步：迁移前置检查

### 3.1 环境依赖清单（缺什么补什么）

| # | 依赖 | 用途 | 缺失时的行为 |
| --- | --- | --- | --- |
| A | **MySQL**（主库） | `agentx_file` 元数据表（启动自动建表，无需手工脚本） | 硬依赖 |
| B | **MinIO**（S3 协议对象存储） | 文件原文落盘 + 预览下载 | 未配 endpoint 不建 Bean；宕机时上传明确报错，应用正常启动 |
| C | **PostgreSQL + pgvector 扩展**（可与主库不同实例） | 大文件分块向量存储（表 `vector_file_info`，自动建） | 未配/连不上 → 全部文件 embed=0 直接加载，RAG 静默降级 |
| D | **Embedding 端点**（OpenAI 兼容，如 DashScope text-embedding-v3，1024 维） | 向量化 | 未配 api-key 不建 Bean，同上降级 |
| E | **多模态端点**（OpenAI 兼容 VL 模型，如 qwen-vl 系） | 图片识别 | 未配 api-key 不建 Bean；图片被问到时返回友好提示 |

要点：C/D/E 全部**可选**。迁移第一天可以只带 A+B 跑通"上传 + 小文件问答"，再逐个点亮 RAG 与多模态。

### 3.2 目标 Agent 能力检查表

| # | 检查项 | 不满足时的补救 |
| --- | --- | --- |
| 1 | **system prompt 可动态拼装**：每轮请求能往 instructions 追加一段文本 | 若 prompt 是静态的，改造为"基础 prompt + 每轮上下文段"两级拼装 |
| 2 | **工具可按请求注入**：工具列表能在每轮构建 Agent 时增删（而非全局固定） | 把 analyzeFile 注册进全局常驻工具也可用，代价是闲聊也占 schema（可接受，先跑通） |
| 3 | **流式事件携带会话/轮次标识**：终态事件（完成/中断）能拿到 sessionId（轮次 ID），供阶段二关联挂 doOnNext | 只拿得到 conversationId 的话，先只做阶段一关联 + prompt 清单（历史回放附件功能放弃或改挂在 conversation 上） |
| 4 | **工具结果以文本回流**：工具返回 String 直接进模型上下文 | 绝大多数 ReAct 框架天然满足 |
| 5 | 有会话历史接口 | 用于历史回放时按轮附附件元数据（可选功能，可后补） |

## 5. Step 2：元数据表 + 实体（整条链路的骨架）

### 5.1 表结构（启动时自动建，幂等）

`agentx_file` 一张表承载全部状态，四个关键字段是设计核心：

```sql
CREATE TABLE IF NOT EXISTS agentx_file (
    id              BIGINT       NOT NULL,
    file_id         VARCHAR(64)  NOT NULL,        -- 业务唯一键 UUID（对外唯一暴露）
    file_name       VARCHAR(255) NOT NULL,
    file_type       VARCHAR(32),                  -- 小写扩展名：类型路由依据
    file_size       BIGINT,
    minio_path      VARCHAR(512),                 -- MinIO 完整 URL
    extracted_text  MEDIUMTEXT,                   -- 解析文本截断版 / 图片识别缓存
    status          VARCHAR(16)  NOT NULL,        -- PROCESSING → SUCCESS / FAILED
    embed           TINYINT      NOT NULL DEFAULT 0,  -- 0=直接加载 1=走 RAG（三路路由依据）
    conversation_id VARCHAR(64),                  -- 阶段一关联（会话窗口）
    session_id      BIGINT,                       -- 阶段二关联（轮次）
    created_at      TIMESTAMP,
    updated_at      TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_file_id (file_id)
);
CREATE INDEX idx_agentx_file_conv ON agentx_file (conversation_id);
CREATE INDEX idx_agentx_file_session ON agentx_file (session_id);
```

建表放在 `FileManageService` 的 `@PostConstruct`，`IF NOT EXISTS` + 静默 `ALTER` 补列补索引（应用自管 schema，迁移零脚本）：

```java
@PostConstruct
void ensureTableExists() {
    JdbcTemplate jdbc = new JdbcTemplate(dataSource);
    jdbc.execute(""" ...上面的 DDL... """);
    tryExecute(jdbc, "ALTER TABLE agentx_file ADD COLUMN session_id BIGINT DEFAULT NULL");
    tryExecute(jdbc, "CREATE INDEX idx_agentx_file_session ON agentx_file (session_id)");
    tryExecute(jdbc, "CREATE INDEX idx_agentx_file_conv ON agentx_file (conversation_id)");
}
private void tryExecute(JdbcTemplate jdbc, String sql) {
    try { jdbc.execute(sql); } catch (Exception e) { log.debug("[file] DDL 跳过: {}", e.getMessage()); }
}
```

## 6. Step 3：三个外部设施装配（每个都可独立缺失）

### 6.1 MinIO（`MinioConfig` + `MinioService`）

```java
@Configuration
@ConditionalOnProperty(name = "data-agent.minio.endpoint")   // 没配 → 不建 Bean
public class MinioConfig {
    @Bean
    public MinioClient minioClient(@Value("${data-agent.minio.endpoint}") String endpoint,
                                   @Value("${data-agent.minio.access-key}") String ak,
                                   @Value("${data-agent.minio.secret-key}") String sk) {
        return MinioClient.builder().endpoint(endpoint).credentials(ak, sk).build();
        // 刻意不做连通性检查：MinIO 宕机应用照常启动，首次上传才触网并明确报错
    }
}
```

`MinioService` 四个方法，注意桶策略是 **publicRead**（预览直读）且 `ensureBucket` 幂等：

```java
public String uploadFile(MultipartFile file, String objectName) throws Exception {
    ensureBucket();  // bucketExists? 不存在则 makeBucket + setBucketPolicy(s3:GetObject 公读)
    minioClient.putObject(PutObjectArgs.builder()
            .bucket(bucketName).object(objectName)
            .stream(file.getInputStream(), file.getSize(), -1)
            .contentType(file.getContentType()).build());
    return String.format("%s/%s/%s", trimSlash(endpoint), bucketName, objectName);
}
public InputStream downloadFile(String objectName) throws Exception { /* getObject */ }
public void deleteFile(String objectName) throws Exception { /* removeObject */ }
```

### 6.2 Embedding 模型（`EmbeddingModelConfig`）

主模型和 embedding 往往是**两家端点、两把密钥**，必须独立 builder，不走 spring.ai.openai 自动配置：

```java
@Configuration
@ConditionalOnProperty(name = "data-agent.embeddings.api-key")
public class EmbeddingModelConfig {
    @Bean
    public EmbeddingModel embeddingModel() {
        JdkClientHttpRequestFactory factory = new JdkClientHttpRequestFactory();
        factory.setReadTimeout(Duration.ofSeconds(300));   // 长文本批量向量化留足时间
        OpenAiApi openAiApi = OpenAiApi.builder()
                .apiKey(apiKey).baseUrl(baseUrl)
                .restClientBuilder(RestClient.builder().requestFactory(factory))
                .build();
        return new OpenAiEmbeddingModel(openAiApi, MetadataMode.EMBED,
                OpenAiEmbeddingOptions.builder().model(model).build());
    }
}
```

### 6.3 PG 向量库独立连接池（`PgVectorConfig`）

只暴露 `JdbcTemplate` 而**不是** `DataSource`——避免污染 DataSource 类型候选，让主库（MySQL）自动配置正常接管：

```java
@Configuration
@ConditionalOnProperty(name = "data-agent.embeddings.store.host")
public class PgVectorConfig {
    @Bean(name = "pgVectorJdbcTemplate")
    public JdbcTemplate pgVectorJdbcTemplate(/* host/port/database/user/password */) {
        HikariDataSource ds = new HikariDataSource();
        ds.setJdbcUrl("jdbc:postgresql://" + host + ":" + port + "/" + database);
        ds.setUsername(user); ds.setPassword(password);
        ds.setDriverClassName("org.postgresql.Driver");
        ds.setMaximumPoolSize(5); ds.setMinimumIdle(1);
        ds.setInitializationFailTimeout(-1);  // PG 暂不可达先放行建池，首次使用才报错
        return new JdbcTemplate(ds);
    }
}
```

### 6.4 多模态（`MultimodalService`）

独立 OpenAiChatModel（VL 模型），HTTP **刻意用 JDK HttpURLConnection**（`SimpleClientHttpRequestFactory`）——规避 Reactor Netty 出站 buffer 对大 base64 图片 body 的卡死（原版踩过的坑）：

```java
@Service
@ConditionalOnProperty(name = "data-agent.multimodal.api-key")
public class MultimodalService {
    private static final String IMAGE_PROMPT =
        "请精简且全面的描述这张图片的内容，包括场景、对象、布局、颜色、文字信息，"
        + "直接输出纯文本描述，不要多余解释和说明，不要使用换行符或特殊符号";

    @PostConstruct
    void init() {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(Duration.ofSeconds(10));
        factory.setReadTimeout(Duration.ofSeconds(timeoutSeconds));
        multimodalChatModel = OpenAiChatModel.builder()
                .openAiApi(OpenAiApi.builder().baseUrl(baseUrl)
                        .apiKey(new SimpleApiKey(apiKey))
                        .restClientBuilder(RestClient.builder().requestFactory(factory)).build())
                .defaultOptions(OpenAiChatOptions.builder().model(model).temperature(temperature).build())
                .build();
    }

    public String imageToText(byte[] bytes, String fileName) {
        UserMessage userMessage = UserMessage.builder()
                .text(IMAGE_PROMPT)
                .media(List.of(new Media(detectMimeType(fileName), new ByteArrayResource(bytes))))
                .build();
        return multimodalChatModel.call(new Prompt(List.of(userMessage)))
                .getResult().getOutput().getText();
    }
}
```

## 7. Step 4：上传编排（FileManageService，D1/D2 落点）

### 7.1 主流程

```java
@Transactional(rollbackFor = Exception.class)
public AgentxFile uploadFile(MultipartFile file) {
    String fileId = UUID.randomUUID().toString();
    String fileType = extractExt(file.getOriginalFilename());   // 小写扩展名

    // ① 先落 DB 占位（PROCESSING）——解析耗时，避免并发重复上传同 fileId
    AgentxFile entity = new AgentxFile();
    entity.setFileId(fileId); entity.setFileType(fileType);
    entity.setStatus("PROCESSING"); entity.setEmbed(0);
    agentxFileMapper.insert(entity);

    try {
        // ② MinIO 落盘，objectName = file-{uuid去横线}.{ext}
        entity.setMinioPath(minioService.uploadFile(file, generateObjectName(fileId, fileType)));
        // ③ 类型路由（D1）
        if (isTextFile(fileType))            handleTextFile(file, entity);
        else if (isImageFile(fileType))      log.info("图片仅落存储，识别延迟到 analyzeFile");
        else                                 log.info("其他类型仅存元数据");
        // ④ 置 SUCCESS
        entity.setStatus("SUCCESS");
        agentxFileMapper.updateById(entity);
        return entity;
    } catch (Exception e) {
        entity.setStatus("FAILED");          // 失败也落库（analyzeFile 可给出状态提示）
        agentxFileMapper.updateById(entity);
        throw new RuntimeException("文件上传失败: " + e.getMessage(), e);
    }
}
```

类型集合（决定路由，按需增删）：文本类 `pdf doc docx xls xlsx ppt pptx txt md csv json html xml rtf odt ods odp eml msg log yml java py`；图片 `jpg jpeg png gif bmp webp`。

### 7.2 文本处理（D2：阈值分流 + 失败回退）

```java
private void handleTextFile(MultipartFile file, AgentxFile entity) {
    ParseResult parseResult = fileParserService.parse(file);   // Tika：全量文本 + 截断版
    entity.setExtractedText(parseResult.getTruncatedText());   // 截断版无条件先存

    if (parseResult.getFullText().length() >= largeFileThreshold) {   // 默认 10000
        if (!embeddingService.isAvailable()) return;              // RAG 不可用 → embed=0 直接加载
        try {
            List<Document> chunks = new OverlapParagraphTextSplitter(500, 50)
                    .apply(List.of(new Document(parseResult.getFullText())));
            embeddingService.embedAndStore(chunks, entity.getFileId());
            entity.setEmbed(1);
        } catch (Exception e) {
            // 向量化失败回退 embed=0，不阻断上传（E01 降级）
            log.warn("向量化失败，回退直接加载: err={}", e.getMessage());
        }
    }
}
```

### 7.3 解析（FileParserService：Tika 一个入口吃所有格式）

```java
private static final int MAX_PARSE_LENGTH = 2_000_000;   // 默认 parseToString 只取 10 万字符，放宽

public ParseResult parse(MultipartFile file) {
    try (InputStream is = file.getInputStream()) {
        String fullText = tika.parseToString(is, new Metadata(), MAX_PARSE_LENGTH).trim();
        return new ParseResult(fullText, truncate(fullText));
    }
}
private String truncate(String text) {   // 默认 20000 字符，截断尾巴注明"细节可通过 RAG 检索"
    return text.length() <= maxTextLength ? text
            : text.substring(0, maxTextLength) + "\n\n... (内容已截断，文件过长；细节可通过 RAG 检索)";
}
```

### 7.4 切分器（OverlapParagraphTextSplitter，直接拷走即可）

按段落 `\n+` 切 + 块内按 chunkSize 填满出块 + 块间 overlap 字符重叠（保住被块边界切断的句子）。**硬约束：overlap < chunkSize**（否则死循环），构造器里校验。参数 `(500, 50)` 是验证过的默认值。完整实现约 90 行，见 `file/OverlapParagraphTextSplitter.java`，无外部依赖可整文件平移。

## 8. Step 5：向量化与 RAG 检索（EmbeddingService，E01 降级落点）

### 8.1 store 手动装配 + 双重降级

```java
@Service
public class EmbeddingService {
    private static final String VECTOR_TABLE = "vector_file_info";
    private static final int EMBEDDING_BATCH_SIZE = 9;   // DashScope 单请求条数上限内的小批量

    @Autowired(required = false) @Qualifier("pgVectorJdbcTemplate")
    private JdbcTemplate pgVectorJdbcTemplate;           // 没配 PG → null
    @Autowired(required = false)
    private EmbeddingModel embeddingModel;               // 没配 api-key → null

    @Autowired
    void init() {
        if (pgVectorJdbcTemplate == null || embeddingModel == null) { return; }  // 降级：RAG 不可用
        try {
            PgVectorStore store = PgVectorStore.builder(pgVectorJdbcTemplate, embeddingModel)
                    .dimensions(dimensions)                              // 必须与配置严格一致
                    .distanceType(PgVectorStore.PgDistanceType.COSINE_DISTANCE)
                    .indexType(PgVectorStore.PgIndexType.HNSW)
                    .initializeSchema(true)                              // 表自动建
                    .removeExistingVectorStoreTable(false)
                    .vectorTableName(VECTOR_TABLE)
                    .maxDocumentBatchSize(100)
                    .build();
            store.afterPropertiesSet();
            this.vectorStore = store;
        } catch (Exception e) {
            log.warn("PgVectorStore 初始化失败，RAG 降级不可用: {}", e.getMessage());  // PG 宕机不阻断启动
        }
    }
    public boolean isAvailable() { return vectorStore != null; }
}
```

### 8.2 入库与检索

入库：注入 `fileid`/`chunkId` 元数据 → 按 9 条/批分批 `doAdd`。`fileid` 是检索过滤的唯一依据，**必须注入**：

```java
public void embedAndStore(List<Document> documents, String fileId) {
    if (vectorStore == null) return;                       // 降级：跳过（embed 保持 0）
    for (int i = 0; i < documents.size(); i++) {
        documents.get(i).getMetadata().put("fileid", fileId);
        documents.get(i).getMetadata().put("chunkId", i);
    }
    for (int i = 0; i < documents.size(); i += EMBEDDING_BATCH_SIZE) {
        vectorStore.doAdd(documents.subList(i, Math.min(i + EMBEDDING_BATCH_SIZE, documents.size())));
    }
}
```

检索（RAG 四步：压缩 → 扩展 → 过滤检索 → 去重合并；任何一步失败返回空列表）：

```java
public List<String> ragRetrieve(String fileId, String question) {
    if (vectorStore == null || !hasText(fileId) || !hasText(question)) return Collections.emptyList();
    try {
        Query query = Query.builder().text(question).build();
        ChatClient.Builder chatClientBuilder = ChatClient.create(chatModel).mutate();

        // ① 压缩：把含指代/上下文的问题压成独立问题（"它第二章说了啥"→"xxx 第二章内容"）
        Query compressed = CompressionQueryTransformer.builder()
                .chatClientBuilder(chatClientBuilder).build().transform(query);

        // ② 扩展：3 个变体 + 原 query，共 4 路（提升召回）
        List<Query> expandedQueries = MultiQueryExpander.builder()
                .chatClientBuilder(chatClientBuilder)
                .numberOfQueries(3).includeOriginal(true).build().expand(compressed);

        // ③ 每变体按 fileid 过滤检索 topK；④ 按 Document id 去重合并
        Filter.Expression filter = new FilterExpressionBuilder().eq("fileid", fileId).build();
        List<String> results = new ArrayList<>();
        Set<String> seenIds = new HashSet<>();
        for (Query eq : expandedQueries) {
            for (Document doc : vectorStore.similaritySearch(SearchRequest.builder()
                    .query(eq.text()).topK(ragTopK).filterExpression(filter).build())) {
                if (seenIds.add(doc.getId())) results.add(doc.getText());
            }
        }
        return results;
    } catch (Exception e) {
        return Collections.emptyList();   // analyzeFile 收到空列表后给 LLM 友好提示
    }
}
```

> 压缩/扩展每问各烧 1+N 次 LLM 调用——这是"大文件值得 RAG"的隐性成本，阈值别调太低。

### 9.1 挂钩点一：analyzeFile 工具（三路路由，D3/D5 落点）

```java
@Tool(description = "针对用户上传的文件，按文件 ID 加载内容，支持文本解析、大文件 RAG 检索和图片识别。"
        + "触发场景：用户问到'文件/文档/PDF/图片/报表/表格'等文件相关词，"
        + "或提到'这个/这些/刚才的'等指代词且可能指代文件，"
        + "或 system prompt 里'当前会话文件'段列出了文件。"
        + "重要：【本次新上传】是一个整体，用户说'这个/这些'时必须挨个 fileId 全部加载。"
        + "大文件传 question 做语义检索。普通对话不要调本工具。")
public String analyzeFile(@ToolParam(description = "文件 ID（UUID）") String fileId,
                          @ToolParam(description = "用户问题，用于大文件 RAG 语义检索") String question) {
    AgentxFile file = fileManageService.getFileInfo(fileId);       // 不存在抛 IllegalArgumentException
    // 路 0：状态提示路由——处理中/失败不执行检索
    if (!"SUCCESS".equals(file.getStatus())) {
        return String.format("文件尚不可用（状态 %s），请稍后重试或提醒用户重新上传。", file.getStatus());
    }
    // 路 1：图片 → MinIO 下载 → 多模态识别（首次后懒写回缓存）
    if (fileManageService.isImageFile(file.getFileType())) return handleImage(file);
    // 路 2：embed=1 → RAG 四步检索
    if (file.getEmbed() != null && file.getEmbed() == 1) {
        List<String> segments = embeddingService.ragRetrieve(fileId, question == null ? "" : question);
        return segments.isEmpty() ? "未检索到与问题相关的内容，可换一种问法重试。"
                                  : render(file, "RAG 检索命中片段", segments);
    }
    // 路 3：其他 → 直接返回 extracted_text
    return render(file, file.getExtractedText(), null);
}

private String handleImage(AgentxFile file) {
    if (hasText(file.getExtractedText())) return render(file, file.getExtractedText(), null);  // 缓存命中
    var multimodalService = multimodalProvider.getIfAvailable();
    if (multimodalService == null) return "图片识别服务未配置（multimodal.api-key 缺失）。";
    byte[] bytes = fileManageService.downloadFileBytes(file.getFileId());
    String description = multimodalService.imageToText(bytes, file.getFileName());
    try { fileManageService.saveExtractedText(file.getFileId(), description); }   // 懒缓存（D5）
    catch (Exception e) { log.warn("识别结果写回缓存失败（不影响本次返回）"); }
    return render(file, description, null);
}
```

description 写法直接照抄——触发场景 + "整组挨个加载" + "闲聊别调"三要素缺一不可，这是实测调出来的 prompt。

工具声明用 Spring AI 的 `@Tool`/`@ToolParam` 注解（目标框架若是别的工具机制，函数体不变，只换声明注解）。注意 MultimodalService 用 `ObjectProvider` 注入而非直接注入——Bean 可能因未配 api-key 而不存在。

}

private void linkFilesFromEvent(List<String> fileIds, AgentStreamEvent evt) {
    Long sessionId = parseOrNull(evt.getSessionId());

    catch (Exception e) { log.warn("link 文件到 session 失败（不影响主流程）", e); }   // 失败仅 warn
}

// ④ 条件注入：会话存在文件（任意轮）才追加 analyzeFile

// 待发送附件：{localId, fileId, fileName, fileType, embed, status: uploading|done|failed, progress, abort}
const pendingFiles = reactive([])

function startUpload(file) {          // 选中立即上传，进度条实时走
  const item = reactive({ fileId: '', status: 'uploading', progress: 0, ... })
  pendingFiles.push(item)
  const { abort } = uploadFile(file, (percent) => { item.progress = percent })
    .then((resp) => { item.fileId = resp.fileId; item.embed = resp.embed; item.status = 'done' })
    .catch(() => { item.status = 'failed' })
  item.abort = abort
}

const sendDisabled = computed(() =>
  pendingFiles.some(p => p.status === 'uploading')   // 上传中禁发
  || pendingFiles.some(p => p.status === 'failed'))  // 失败需先移除

function send() {
  const fileIds = pendingFiles.filter(p => p.status === 'done' && p.fileId).map(p => p.fileId)
  pendingFiles.splice(0)               // 发送即清空待发送区
  s.messages.push({ role: 'user', content: query, attachments })   // 气泡立即显示附件

}

| `dimensions` 与 embedding 模型实际维度不一致 | 入库/检索报维度错误 | text-embedding-v3 是 1024，两处严格一致 |
| embedding 批量超 DashScope 上限（10） | 413/参数错误 | 9 条/批（§8.2） |
| 多模态走 reactor-netty | 大 base64 图片 body 卡死 | JDK SimpleClientHttpRequestFactory（§6.4） |
| overlap ≥ chunkSize | 切分死循环 | 构造器校验（§7.4） |
| 上传时识别图片 | 上传慢 + 每张图都烧钱 | 懒识别 + 写回缓存（D5） |
| prompt 只列文件不写触发规则 | LLM 不调工具 / 只调第一个文件 | §9.2 的【触发规则】整段照抄 |
| 阶段一关联放在 ReAct 启动之后 | 本轮 prompt 反查不到刚上传的文件 | linkToConversation 必须先于 buildAgent（§9.3） |
| `agentx_file`/`vector_file_info` 出现在 Agent 可见 schema | LLM 试图对文件表写 SQL | schema 排除 `agentx_*`；向量表在独立 PG 天然隔离（不变式 6） |
| Tika 用默认 parseToString(is) | 超 10 万字符被静默截断，RAG 语料缺失 | 显式传 MAX_PARSE_LENGTH=200 万（§7.3） |
