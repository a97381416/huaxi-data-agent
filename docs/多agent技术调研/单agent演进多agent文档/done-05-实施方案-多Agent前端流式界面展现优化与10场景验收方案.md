## 1. 背景与现状痛点

在多 Agent 落地（`M-SA1 ~ M-SA5`）后，后端已支持 4 大垂类有状态子 Agent（数据分析专员、资料填报专员、审核审批专员、驳回重提专员）的并发委派、事件透传与历史回放，但原 `ChatView.vue` 前端展现存在以下痛点：

1. **子 Agent 与普通工具混排**：单次委派仅展示为普通工具行；同轮并行委派 2 个子 Agent 时会被折进 `🔍 查阅 · N个工具` 组，子步骤直接丢失。
2. **主会话易刷屏但细节不可见**：运行中将子工具全部平铺在主聊天流下容易拉长页面；同时子 Agent 的思考过程（`thinking`）、派发任务指令（`task` Prompt）和子专员自身输出（`text`）被过滤，无法查看。
3. **缺少独立子会话视图**：无法像参考原型一样在主会话只看精简进度与结论、点击后在右侧独立多 Tab 面板中按需下钻查看子 Agent 完整执行流水。

---

## 2. 核心设计思路与交互定稿

核心原则：**主次分离、按需下钻**。

已定稿的 3 项关键交互决策：
1. **子 Agent 独立会话面板形态**：从页面**右侧滑出抽屉**（默认宽 `500px`，支持一键加宽至 `760px`，窄屏自动浮层覆盖；打开时右侧执行计划面板自动让位，切换会话自动关闭）。
2. **多子 Agent 并行排列方式**：主会话中采用**纵向紧凑卡片堆叠**，保证专员名、实时耗时、任务简述和最新 1 步动态清晰不截断。
3. **抽屉打开时机**：**默认不自动弹开**（保持主会话清爽），点击卡片「查看详情 >」打开；打开后同消息中所有子 Agent 以顶部多 Tab 形式呈现，支持随时切换。

## 3. 技术改造方案

### 3.1 后端最小字段补齐（历史回放对齐）
- 修改文件：`backend/data-agent-server/src/main/java/com/llmetor/dataagent/dataagent/session/SessionService.java`
  1. `loadSubSessions()` 联查 `agentx_monitor_session` 时同步取回 `status` 与 `duration_ms`，回填到父委派工具节点（还原耗时及 `failed / interrupted` 终态）；
  2. `buildTimeline()` 保留子会话的 `text`（专员输出）进入 `subSteps`，并调用 `loadThinkDurations(subConvId, sub.sessionId())` 补齐子 Agent 思考耗时。

### 3.2 前端组件化与主会话接入
| 文件 | 职责说明 |

## 4. 多 Agent 10 大 UI 测试场景清单

### 场景 1：单子 Agent 委派（运行中）
- **业务场景**：用户提问统计本月各项目填报进度并画图，主 Agent 派出「数据分析专员」。
- **验收要点**：主会话只展示 1 张紧凑卡片（运行中 + 实时耗时 + 任务简述 + 最新 1 步动态 + 已查阅/已执行统计），不刷屏。

```text
+-------------------------------------------------------------+
| ● 🤖 数据分析专员  [运行中 · 15.0s · 内部 3 步]   查看详情 > |
|   任务：统计本月各项目填报进度并生成柱状图                    |
|   ↳ (转圈) 正在执行 执行查询 · SELECT project_name, ...      |
|                                   已查阅 2 项 · 已执行 1 步  |
+-------------------------------------------------------------+
```

### 场景 2：子 Agent 独立会话抽屉（按需下钻）
- **业务场景**：点击主会话中的子 Agent 卡片，右侧滑出独立会话抽屉。
- **验收要点**：顶部 Tab 栏 + 放大/关闭按钮、模型标识、委派任务 Prompt 气泡（超长可展开）、思考/工具/专员输出完整时间线（点任意工具行可看入参与返回）、最终汇报、底部实时状态栏。

```text
+---------------------------------------------------+
| [● 数据分析专员]                        [⤢] [✕]   |
+---------------------------------------------------+
|             正在使用 海方-glm / GLM-5.3            |
|  +---------------------------------------------+  |
|  | 委派任务指令：按月统计近 3 个月合同变更趋势... |  |
|  +---------------------------------------------+  |
|  ▼ 已查阅 2 项，已执行 1 步 · 思考 1 次            |
|  | 🧠 思考 持续了 1.8s                      v     |
|  | ✓ 已读取 查表清单                        0.3s  |
|  | ✓ 已执行 执行查询  SELECT month...       1.5s  |
|  | [专员输出] 已核对近 3 个月合同变更明细...       |
|  +---------------------------------------------+  |
|  | 返回给主会话的最终汇报：近 3 个月共变更 27 次… |  |
|  +---------------------------------------------+  |
+---------------------------------------------------+
| ✓ 已完成 · 共 3 步                   耗时 12.4s   |
+---------------------------------------------------+
```

### 场景 3：多子 Agent 并行执行
- **业务场景**：同轮同时派出「数据分析专员」和「审核审批专员」。
- **验收要点**：主会话纵向堆叠 2 张独立卡片（不折叠进普通工具组）；点开右侧抽屉，顶部显示 2 个带状态点的 Tab，支持自由切换。

### 场景 4：并行子 Agent 一先一后返回（交错完成态）
- **业务场景**：「审核审批专员」先完成返回结论，「数据分析专员」仍在运行。
- **验收要点**：先完成的卡片立即切为绿勾已完成态并露出结论摘要，未完成的卡片保持蓝点转圈计时，互不干扰。

### 场景 5：全部完成后的收起态与展开态
- **业务场景**：子 Agent 全部完成且主 Agent 输出最终汇总答案。
- **验收要点**：默认折叠为顶部摘要条 `已工作 · 32.1 秒 · 协作 2 个专员（数据分析专员、审核审批专员）`，下方直接露出最终回答；点击摘要条展开全部过程与卡片。

### 场景 6：多子 Agent 串行接力（先 A 后 B）
- **业务场景**：先派「数据分析专员」定位异常项目，主 Agent 拿到结果后过渡说明，再派「资料填报专员」拉取该项目填报节点。
- **验收要点**：按时间顺序分段渲染「专员 A 完成卡片 → 主 Agent 过渡说明 → 专员 B 运行/完成卡片」，右侧抽屉按调用顺序排列 Tab。

### 场景 7：子 Agent 触发高危确认卡（人机协同 HITL）
- **业务场景**：「资料填报专员」或「审核审批专员」签发 `ct_xxx` 确认令牌。
- **验收要点**：确认卡直接冒泡渲染在主会话正文区，展示 diff/影响说明与「✅ 确认执行 / 取消」按钮，不隐藏在子抽屉内。

### 场景 8：内部局部报错自愈 & 整体超时/失败
- **业务场景**：
  - **8a 局部报错自愈**：子 Agent 内部某工具报错后自行重试成功 → 主卡片为绿勾完成态，并带 `含 1 次重试` 角标；抽屉内可看到红叉失败行与后续绿勾成功行。
  - **8b 整体超时（180s）/彻底失败**：卡片呈橙色超时态或红色失败态，底部直接展示原因，点详情可查看最后卡在哪一步。

### 场景 9：用户强停（父子级联中断） & 历史会话回放
- **业务场景**：
  - **9a 强停中断**：点击停止按钮，父子卡片同步切为灰色 `⏸ 已中断` 态，保留中断前已执行步骤可供点开排查。
  - **9b 刷新/切换历史会话**：通过 `SessionService.buildTimeline()` 还原出与实时跑完一致的折叠态、子卡片耗时/状态与右侧多 Tab 抽屉。

### 场景 10：子 Agent 后台长跑 + 主会话阶段简报 + 最终汇总（前端预留，后端见 `todo-06`）
- **业务场景**：后台专员耗时较长时，主 Agent 先快扫轻量信息并输出「阶段性简报」，底部出现 `⏳ 等待后台专员返回（X/Y 已完成），结果到达后将自动汇总…`；全部完成后自动收起过程并输出最终全景汇总。
- **验收要点**：前端 UI 已完全支持异步交错渲染，可在 `/test/multi-agent-ui` 场景 10 一键切换演示“后台运行+简报态”与“全部完成汇总态”。

## 5. 验收方式与验证结果

1. **交互验收台**：启动前端后访问 `/test/multi-agent-ui`，左侧一键切换全部 10 大场景，点击卡片可测试右侧多 Tab 抽屉、加宽、展开参数/结果及场景 10 状态切换。
2. **真实对话验收**：在 `/chat` 页面发起多 Agent 提问（单专员问数、跨领域并行问答、填报提审确认卡、运行中点停止、刷新页面回放历史会话）。
3. **构建验证**：
   - 前端 `npm run build`（Vite 生产构建）：通过；
   - 后端 `mvn -pl data-agent-server -am compile -DskipTests`：通过（`BUILD SUCCESS`）。
